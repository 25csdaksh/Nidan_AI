# NIDAN AI API Conventions

## 1. Base URL & Versioning
All backend API routes follow the standard version prefix:
```
https://api.nidan.ai/api/v1/{module}/{resource}
```
Example:
- `GET /api/v1/health`
- `GET /api/v1/patients`
- `POST /api/v1/reports/upload`
- `GET /api/v1/lab/abnormalities`

## 2. Clinical Decision Support System (CDSS) Disclaimer Headers
Every HTTP response generated by the NIDAN AI backend MUST include the following response header automatically injected by the `DisclaimerHeaderMiddleware`:

```http
X-CDSS-Disclaimer: NIDAN AI provides assistive clinical insights for licensed medical professionals. It is not an automated diagnostic system.
X-CDSS-Confidence-Policy: Human-in-the-loop review required for all clinical decisions.
```

## 4. HTTP Status Codes
- `200 OK`: Successful GET, PUT, PATCH.
- `201 Created`: Successful POST entity creation.
- `202 Accepted`: Asynchronous job queued (e.g. document extraction task).
- `204 No Content`: Successful DELETE.
- `400 Bad Request`: Validation failure or malformed payload.
- `401 Unauthorized`: Missing or expired JWT token.
- `403 Forbidden`: Insufficient role or clinician permissions.
- `404 Not Found`: Resource does not exist.
- `422 Unprocessable Entity`: Schema / Pydantic validation error.
- `429 Too Many Requests`: Rate limit exceeded.
- `500 Internal Server Error`: Unhandled application error (masked in production).

## 5. Medical Document Endpoints (Phase 1)
- `POST /api/v1/medical-documents`: Ingest PDF/image file for a patient with SHA-256 verification and async processing.
- `GET /api/v1/medical-documents/{id}`: Fetch document metadata and processing state.
- `GET /api/v1/medical-documents/{id}/status`: Fast status polling endpoint (`{ "id": "...", "status": "QUEUED" | "PROCESSING" | "COMPLETED" | "FAILED" }`).
- `GET /api/v1/medical-documents/{id}/download`: Securely stream the medical document bytes with RBAC checks and audit logging.
- `DELETE /api/v1/medical-documents/{id}`: Soft-delete medical document following HIPAA data retention rules.
- `GET /api/v1/patients/{patient_id}/medical-documents`: Paginated list of a patient's documents with filters for `document_type` and `processing_status`.

## 6. Authentication & Authorization
- **Bearer Token**: `Authorization: Bearer <jwt_access_token>`
- **Roles**:
  - `ADMIN`: System administrator
  - `DOCTOR`: Licensed physician with patient document ingestion and verification permissions
  - `CLINICIAN`: Clinical support staff with upload and viewing permissions for assigned patients
  - `PATIENT`: Patient with strict read-only access limited to their own records
  - `AUDITOR`: Read-only compliance and HIPAA auditing role
